# Skilit Community Standards

Skilit is an open-source design intelligence project for people and AI agents. We want a technically rigorous, respectful, and secure community.

## Expected behavior

- Assume good intent while evaluating claims based on reproducible evidence.
- Respect contributors regardless of experience, identity, background or location.
- Give specific, actionable feedback about code and behavior, not people.
- Keep discussion professional and accessible. Follow the project's English-only repository artifact rule.
- Protect private user data, workspace content, security credentials and unpublished assets.
- Follow all relevant licenses, contributor permissions and source provenance requirements.
- Disclose relevant conflicts of interest and distinguish personal opinions from project decisions.

## Unacceptable behavior

Harassment, discriminatory conduct, personal attacks, threats, trolling, doxxing, or the disclosure of private credentials or information are not acceptable. Do not pressure maintainers to bypass required engineering, security or review gates. Misrepresenting a tool run, security review, benchmark, contributor approval or source license is not acceptable.

## Scope

These standards apply to issues, PRs, reviews, discussions, shared project spaces and representations of Skilit in public or private community activities.

## Reporting concerns

For repository discussion or conduct concerns, use GitHub's report or moderation mechanisms where available, or contact a repository maintainer through an appropriate **private** channel. Do not publish sensitive accounts or allegations unnecessarily.

For security vulnerabilities, follow the security constraints in [SECURITY.md](SECURITY.md) and use private vulnerability reporting if it is enabled. A public bug report is not the correct venue for exploit details.

No external email address or response SLA is claimed by this document; repository maintainers should explicitly configure contact and moderation channels before broad public community onboarding.

## Enforcement

Maintainers may request edits, hide or remove inappropriate content, restrict participation, and escalate severe incidents through the hosting platform's moderation tools. Reports should be assessed fairly and confidentially as appropriate. Enforcement decisions must be based on the behavior and project policy, not on personal characteristics.

These standards supplement the canonical [GOVERNANCE.md](GOVERNANCE.md) and [SECURITY.md](SECURITY.md); they do not replace either.
